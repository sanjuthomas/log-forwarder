1. Coverage model
-----------------

Three layers matter for config confidence:

  L1  config.Load + Validate()     CFG-1 (all example YAMLs)
  L2  package unit tests           internal/config, pipeline, watcher, sink, …
  L3  integration E2E + smoke      internal/integration, scripts/*-smoke.sh

Gap: L1 does not prove runtime behavior. Most L3 tests use harness-built config
(regex tab lines, file sink), not the checked-in example files.

5. Suggested implementation order
-------------------------------

  1. CFG-2 scaffold (unlocks confidence in all 21 example configs at runtime)
  2. E2E-28, E2E-27 (on_full — highest operational risk)
  3. E2E-30 (hibernate wake — code exists, only E2E missing)
  4. E2E-31 (readiness — docker smoke configs already set readiness)
  5. E2E-24, E2E-29 (transform/sink variants)
  6. Remaining P2 items
